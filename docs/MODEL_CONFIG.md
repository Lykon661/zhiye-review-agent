# 模型配置

页面入口是右上角“模型配置”。结构参考 [pi-ai 的 Providers and Models、Auth、Custom Providers](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md)：服务商管理连接与凭据，模型管理协议、能力与调用参数，再由一个明确的选择决定复习任务使用哪个模型。

## 接入和切换

1. 在左侧选择服务类型，点击“添加服务商”。可以添加同一种服务的多个连接，例如不同账户或不同兼容网关。
2. 填写显示名称、接口根地址、凭据方式和超时。根地址不包含 `/chat/completions`、`/responses`、`/messages`。
3. 从该服务商的内置目录选择模型，点击“添加”；也可以手动填写模型 ID。兼容接口可点击“获取服务模型列表”，然后从获取的列表添加。
4. 配置模型协议、上下文窗口、最大输出及视觉、推理能力。目录只用于提供初始值；远端 `/models` 只提供 ID 时不会猜测能力。
5. 点击“选择用于复习”，检查底部“保存后使用”，再点击“保存配置”。上方“正在使用”显示实际保存的配置。

切换服务商或模型的编辑页不会立即修改实际使用的模型。保存会保留其他服务商、凭据和模型；新增模型不会替换已填写的接口地址。也可以点击“暂不使用模型”，保存后停止模型接入。

“删除服务商”和“移除模型”会在固定底栏显示确认。确认后通过独立接口立即删除已保存项，无需再点击保存，不受其他草稿中的空模型 ID 或错误参数影响；其他未保存修改仍保留。删除正在使用的项会同时停止该模型接入。删除服务商会清除对应订阅凭据，新建但尚未保存的模型则只移除本地草稿。

未接入的服务商可先保存名称与模型作为草稿，接口地址和密钥可稍后补全。模型 ID 必须非空，在同一个服务商下唯一。使用中的模型必须具有完整连接与凭据。正在处理复习任务时，前后端均阻止保存和切换。

## 凭据

- **API Key**：每个服务商保存自己的密钥，同一连接下的模型共用。留空保留该连接的已有密钥，输入新值替换；勾选清除会删除密钥。修改接口地址后，留空不会将原密钥带到新地址。
- **后端环境变量**：内置服务可选择对应变量，例如 `DEEPSEEK_API_KEY`。变量名称显示在页面，只在后端读取；不会覆盖显式选择的 API Key。修改 `.env` 后需要重启后端才能重新加载变量。
- **无需密钥**：用于自定义或本地服务，Ollama、LM Studio 的本地预设会默认选择这一方式。
- **自定义请求头**：填写字符串值的 JSON 对象；留空保留已有请求头，清除选项会删除。认证头由 API Key 生成，无需重复填写。请求头值与密钥都不会回显。

## 模型订阅登录

左侧“添加连接”中的“模型订阅登录”分组列出当前 pi-ai 内置的订阅服务，包括 ChatGPT、ChatGPT/Codex、Claude、GitHub Copilot、Kimi、xAI 和 Meta。已有的对应服务商也可以在“接入方式”中选择“模型订阅登录 / OAuth”。API Key 的 Coding Plan 服务仍使用自己的 API Key 接入方式。

1. 添加订阅连接，点击“登录订阅账号”。
2. 页面根据服务商流程显示登录方式、授权链接、设备验证码或授权码输入框。点击链接后由你在浏览器完成登录；浏览器回调成功时会自动更新状态，也可按提示粘贴授权码或完整回调地址。
3. 登录成功后，从内置目录添加账号可用的模型，点击“选择用于复习”，最后点击“保存配置”。授权本身不会保存其他表单修改。

订阅使用服务商原生认证与协议，根地址和模型协议不能任意改为网关地址。账号专属地址、认证头和令牌刷新由 pi-ai 的原生 provider 处理；刷新后的令牌写回该连接独立的本机凭据文件。刷新失败时需重新登录，调用不会回退到环境变量中的 API Key。

授权凭据保存在 `data/model-auth/<连接标识>.json`，访问令牌和刷新令牌不会返回浏览器。登录会话最多十分钟，关闭配置窗口会取消尚未完成的登录。“退出登录”清除该连接的订阅凭据，正在使用的订阅模型会停止接入；该账号在服务商的其他登录会话不受此本机退出操作影响。

内置订阅入口来自项目锁定的 pi-ai 版本，登录成功不代表账号具备目录中全部模型的使用权限，具体权限由服务商决定。AWS 签名或云项目认证仍不属于当前页面的接入方式。

## 模型参数

支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Gemini 和 Mistral Conversations，另有专用于 ChatGPT/Codex 订阅的 Codex Responses 协议。网关可能提供与原厂不同的协议，应以实际服务文档为准。

上下文窗口用于安排输入预算，最大输出用于限制模型请求；最大输出不能超过上下文窗口。勾选图片输入或推理能力不会让服务获得对应能力，需要与实际模型一致。

思考强度为“服务商默认”时使用服务的默认调用方式；明确选择关闭或具体强度时，通过 pi-ai 的统一 `streamSimple` / `completeSimple` 接口转换成服务商参数。原厂目录中不支持的强度不会作为常规选项提供，运行层也会拒绝不支持的选择。自定义模型的可用强度需由服务商确认。

温度可留空：普通模型使用应用默认温度 0.15，推理模型默认不发送温度；填写后传给对应协议适配器，服务是否接受该参数取决于模型。

兼容参数默认采用 pi-ai 的协议检测和原厂模型元数据。可手动覆盖 Developer 角色、流式 token 统计、`store`、`reasoning_effort`、严格工具定义，以及 Chat Completions 的输出字段名和思考格式。例如本地服务拒绝 Developer 角色时设置为“不支持”，旧兼容接口可以选择 `max_tokens`。切换模型协议会清除该模型已有的兼容覆盖，避免携带另一协议的参数。

只有模型 ID、协议与接口根地址都匹配原厂目录时，调用层才继承原厂模型的协议元数据。配置的视觉能力、上下文、输出上限、温度和思考强度始终用于实际调用。

## 目录与连接检查

内置目录随项目锁定的 pi-ai 版本提供，不保证某个账户具有模型权限。目录读取不请求模型服务；服务模型列表由用户点击获取，适用于提供 `/models` 的 OpenAI 兼容服务，失败时仍可手动添加。

“检查所选模型”发送一次短文字请求，使用当前编辑的连接和模型，不保存、不切换实际配置；可能产生少量 API 费用，也不会确认视觉能力。它只检查所选模型，其他服务商草稿不影响检查。

## 配置保存与升级

配置保存于 `data/model-config.json`，结构版本为 2，包含 `providers` 和 `active`。文件存放本机密钥与请求头，不应提交到版本库。页面不会将凭据写入浏览器存储，模型调用通过后端将凭据传给 Node 子进程的标准输入。

原来的单模型 JSON 配置和 `.env` 中的 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` 会载入“原有模型配置”。升级读取时不修改原文件；在页面保存时才写入新版结构。保存的配置优先于旧 `.env`。旧 `/system/model-config` 接口继续返回当前使用的模型，新的管理接口为 `/system/model-registry`。

本次重构未运行应用、构建、测试或真实服务调用，页面交互与各服务商协议需由使用者测试。
