# 课程知识检索

课件、笔记的知识检索按 PPT/PDF 的页、Word/文本的小节组织。原始 Block 和 Chunk 保留；新索引将同页标题、正文、表格、已识别的公式连在一起，每个向量片段都带本页标题，召回后读取对应整页/小节原文。重复算法标题会保留，只过滤能够识别的重复页脚。

## 升级与使用

等待现有任务完成后重启后端。首次检索某门课程时，会从已经保存的解析文本增量建立新索引，可能比平常慢；不需要重新上传、重新解析或重新做 OCR。新上传资料入库时同时更新索引。

普通问题采用页/小节 BM25 与向量混合召回，再用当前配置的模型判断正文相关性。综合列举、对比问题还会读取相关课件的真实标题，确定子主题和比较维度，分别召回并对缺项补搜一次。目录按相关文件交替读取，避免前面的长课件挤掉后面的文件。选择了章节时，只在选定章节内检索。

重排分批执行。复杂度、稳定性等覆盖判断必须带候选正文中的逐字引用，程序校验引用存在；模型生成的事实不写入课程证据。重排失败时保留混合召回的原文，诊断标记为回退或部分重排，此时覆盖判断尚未完成。

讲解和普通复习对话按模型设置中的上下文窗口估算 token，并预留输出与消息开销。估算没有使用服务商的精确 tokenizer。优先提供整页原文，放不下时摘取原文段落并记录省略；引用被省略后，对应维度不会继续标记为已有依据。模型设置中的窗口需与实际服务一致。

综合请求会增加范围规划、重排的模型调用，必要原文会发给当前配置的模型服务。不能保证未解析的图片、公式或课件未写出的结论被检索到；缺项需要在回答中说明，不能根据“相关分数高”认定已覆盖。

## Token 开销优化

重排按单个来源缓存已经校验的评分、主题和原文引用，包括判为无关的候选。相同请求、主题、比较维度、课程版本、章节范围、模型配置及原文摘录下，只将未命中的候选发送给模型。缓存命中仍使用当前读取的原文与定位，并再次检查引用存在。资料、范围、模型或摘录改变后重新评估；失败和预算未覆盖的候选不缓存。缓存仅在同一后端进程内有效，最多4096条，重启后清空；首次请求仍需正常重排。

复习空间的行动规划器只接收证据数量、主题及覆盖缺口，移除重复的课程原文预览、历史讲解和参考答案，缩短历史摘要与文件目录。当前用户请求完整保留。原文及较完整的对话、答题上下文仍直接交给讲解工具，召回范围和最终证据预算保持原有规则。

明确要求讲解、列举或对比时，若所有已规划主题与维度都有核实的课程依据，且这些依据实际能装入讲解提示，检索完成后直接进入讲解，省去一次行动规划调用。出题、结束、意图不明确、重排失败、目录省略或证据有缺项时保留正常规划流程。该路径仍保留检索与讲解的行动记录、取消检查和课程版本检查。

## 每条回答的 Tokens

复习空间和普通复习对话在回答下方显示本次 Tokens、输入、输出及模型调用次数，展开可查看行动规划、检索与重排、回答与出题的分项。统计使用服务商经 pi-ai 返回的用量，包含生成这条回复触发的模型调用，不含异步后台记忆整理及本地向量计算。重排缓存命中没有新增模型调用；失败调用有已返回的用量时仍计入。批量出题会一次生成整批，消耗计入第一条回复，后续展示已生成题目不重复计入。

输入包含缓存读取/写入，推理 Tokens 已包含在输出中，不重复相加。不展示金额。兼容接口未返回用量时显示“服务商未返回”；部分调用缺失时只显示“本次已知 Tokens”并注明缺失次数，不将缺失用量当成0，也不冒充精确估算。

用量随消息保存，重新打开会话可查看。旧消息没有记录时显示“Tokens 未记录”，无法恢复历史真实消耗。后端启动会为原有 messages 表补充可空的 token_usage 字段，不改变历史内容。流式协议和模型桥接层已更新，重启后端后开始记录新回答。

## 复习空间的章节范围

输入框上方的“搜索范围”默认是全部章节，可以多选有已就绪知识资料的章节，点击“应用范围”保存。新对话默认全部章节；已有对话会保存各自的选择，重新打开后恢复。应用范围仅修改设置，不调用模型；后续发送消息或重试才会检索和生成回答。

限定范围后，课程目录、文件清单、关键词与向量召回、范围规划和缺项补搜均只使用所选章节。更换范围会清除当前缓存的检索证据，重排缓存也按章节隔离；历史回答、已生成的题目和作答草稿保留。新回答下方标明该条实际使用的搜索范围，避免与后来修改的设置混淆。

限定章节的讲解仍缺少明确原文依据时，可点击“扩大到全部章节并重新回答”。这会保存全部章节范围并重新提交刚才的问题，会产生一次新的回答及相应模型消耗；系统不会自动扩大用户选择的范围。较小范围可能降低规划与重排消耗，具体节省量取决于候选数量及实际回答长度，可结合每条回答的 Tokens 对比。

创建对话的请求支持 `chapter_ids`，空数组表示全部章节；修改接口为 `PUT /review-spaces/{space_id}/scope`，请求包含 `revision` 和 `chapter_ids`。接口检查章节归属和资料状态，并阻止生成中的范围变更及过期版本覆盖。不需要重新上传资料或迁移数据库。

## 复习空间诊断

复习空间会保存本轮检索和讲解实际使用的材料。只读接口：

```text
GET /review-spaces/{space_id}/retrieval-report
GET /review-spaces/{space_id}/retrieval-report?message_id={message_id}
```

可在后端的 `/docs` 页面找到接口，填入复习空间 ID。默认返回最近一条保存了检索诊断的讲解；指定消息 ID 可查看该条讲解。打开接口不会重新检索或调用模型。历史讲解没有诊断时，`available` 为 `false`。

- `report.topic_plan`：本次需要覆盖的子主题，以及来自实际目录的定位。
- `report.queries`：各主题召回数量、缺项补搜查询。
- `report.retrieval_errors`：个别子查询的向量/匹配错误；其他已经找到的原文仍会保留。
- `report.rerank`：重排方法、实际评估数量、回退情况、引用与评分。`partial_rerank` 表示只有部分候选完成重排。
- `report.rerank.cache_hits`、`report.rerank.model_calls`：本次含补搜的重排缓存命中来源数与模型调用数；命中数可包含补搜对同一来源的复用，不是独立文件数。
- `report.planner`：本轮行动规划的 `model_calls`、省去的 `skipped_calls` 及实际发送的规划输入估算 `input_tokens_estimate`。不含范围规划、重排和最终讲解，也不是服务商账单 token。
- `report.coverage`：检索阶段的材料与比较维度覆盖。
- `report.selected`：重排后选中的页/小节和真实文件定位。
- `report.supplied`、`report.supplied_coverage`：实际装入讲解提示的材料及重新核算的覆盖。
- `supplied_materials`：实际装入讲解的原文摘录、定位和省略标记。

诊断中的“未覆盖”表示本轮没有核实到该维度的原文依据，不等于整个资料库绝对没有相关内容。原文片段校验也不能代替对模型语义判断的人工核对。

## 建议重试的问题

1. 在原来的复习空间发送“帮我列举对比一下课程里各种排序算法”。旧检索缓存会在下一轮自动更新。
2. 对照课件里的实际算法种类，检查是否覆盖 lec7-1 到 lec7-5 中相关内容，不预设课件未讲的算法也必须出现。
3. 追问“只对比快排、堆排和归并排序的时间复杂度、空间复杂度和稳定性”，核对原文和缺项说明。
4. 查看诊断中选中的页与实际装入的页，尤其检查被摘取的原文是否遗漏关键复杂度分析。

索引修复提示出现时，等待上传处理完成后使用资料库的“重新建立索引”。该操作会完整重建原有片段与新的知识向量索引，再切换到新索引目录。

这次实现提供了回归用例，尚未运行测试、构建或真实模型验收；实际效果由用户重启项目后确认。
