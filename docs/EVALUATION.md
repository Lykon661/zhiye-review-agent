# 数据结构课程评测

脚本默认选择本机保存的“数据结构”课程，使用 `scripts/evaluation/data_structures.jsonl` 中的 30 道固定题。题集依据当前 lec2–lec9 课件的页码、代码和原文准备，包括 8 道知识题、5 道中文问英文资料、5 道代码题、5 道综合比较、5 道资料外题，以及 2 个复习空间流程场景。其中一个场景包含追问，另一个要求生成两道新的栈简答题。

已有一次完整运行（2026-10-10）：动作完成率 28/30，标注原文进入最终提示 32/48；AI 逐题复核的核心回答通过 25/30、严格任务通过 21/30。汇总见 [README](../README.md#评测)。之后的修复尚未重新评测，下文的指标口径适用于今后的对照运行。

## 运行

在项目根目录的 PowerShell 执行。无需启动网页或另一台评测服务器，但需先在项目页面保存模型配置，且完成课程资料处理。

先用三道题确认运行条件和模型开销：

```powershell
uv run python .\scripts\evaluate_data_structures.py --limit 3 --judge
```

完整评测：

```powershell
uv run python .\scripts\evaluate_data_structures.py --judge
```

只检查树类型与排序综合覆盖：

```powershell
uv run python .\scripts\evaluate_data_structures.py --case ds19 ds20 --judge
```

不加 `--judge` 时只运行真实复习流程并记录证据、动作和用量，答案评分留待人工填写。加上 `--judge` 会额外使用当前同一个模型逐题评审，产生额外调用和费用；评审用量与系统回答用量分别统计。综合问题本身也可能触发多次规划、重排和检索。

如果课程改名，使用 `--course-name "新名称"`；存在同名课程时使用 `--course-id "课程ID"`。`--output` 可以指定一个尚不存在的输出目录；脚本不会覆盖旧结果。`--label before` 或 `--label after` 可给不同版本的报告命名。

## 如何使用当前资料而不影响复习记录

脚本通过 SQLite backup 从当前数据建立一致性副本，只读原数据库；模型配置也复制到临时目录。所有新会话、生成题目、业务状态和重建的向量索引均写入 `.cache/evaluations/` 的独立临时目录，结束后关闭服务并清理副本。原上传文件不重新解析，不重新 OCR，也不直接复制正在使用的 Chroma 二进制文件。

索引由副本里已经保存的 Block/Chunk 重建，因此评测反映当前解析文本与当前检索实现，不验证原在线索引是否损坏。首次重建会耗费本地向量计算时间，可能需要获取尚未缓存的向量模型；初始化耗时单独记录，不计入回答耗时。

保留副本中原有的学习记录作为统一起点，不启动后台记忆整理线程，不提交生成题目的作答。每道独立题清空重排缓存，追问保留该题自己的会话和证据。报告不是机器冷启动性能测试。

若使用订阅 OAuth，凭据仍使用原有的加锁凭据存储，正常 token 刷新会共享认证状态，避免刷新临时凭据后丢失新的 refresh token。课程业务数据仍在副本内。报告和清单不导出 API Key、请求头或订阅 token。

## 输出

脚本打印结果目录，默认位于 `data/evaluations/<UTC时间戳>/`：

| 文件 | 用途 |
| --- | --- |
| `report.md` | 汇总、分组结果、逐题失败线索和局限 |
| `results.jsonl` | 每题完整回答、每轮耗时、实际提示证据、检索诊断、行动记录、分项用量和辅助评审 |
| `results.csv` | 适合人工复核的表格，包含判定列 |
| `gold.json` | 绑定当前文件 ID/页码/文件哈希的题目、判定要点和标注原文 |
| `manifest.json` | 课程版本、资料清单、模型设置、题集/解析文本/学习记录/代码哈希、初始化信息 |
| `metrics.json` | 可供后续比较的结构化汇总 |

运行中逐题追加并刷新 JSONL；单题失败继续下一题。Ctrl+C 会保留已获得的结果；没有返回的用量标为未知。初始化失败会记录失败原因，不生成虚假的成功指标。范围或原文标注过期时，在任何模型评测调用前停止并指出对应题目。

## 指标口径

- **动作完成率**只验证服务结束状态、是否讲解/出题、题型、题数和章节范围，不证明回答内容正确。
- **标注出处页被选中**检查指定文件和幻灯片被选入检索结果，不说明所需原文已进入模型提示。
- **最终标注原文覆盖率**检查要点对应的参考引用是否出现在该文件/页实际打包的文本中。一个要点的多个引用视为可替代证据，命中其中一个即可。它是公开诊断集的参考片段覆盖，不是穷举正确证据的 Recall@K，也不是答案准确率。等价出处可能造成保守的漏命中，需要人工核对。
- **辅助要点评分**按每个标注要点给 0/1/2 分，并验证正分引用确实来自回答，以及该要点的标注原文或实际提示中的课程原文。后者需返回准确的来源 ID，网页和未送入提示的上下文不计为课程替代证据。评审判断另一页的原文是否支持同一要点，不能仅因不是标注页而扣分。引用比较允许 Markdown 加粗等格式差异和 LIFO 等短术语，仍拒绝改写、拼接或不存在的引用。校验失败最多额外修复一次，相关用量独立计入评审消耗。逐字引用校验不能证明语义判断正确，同模型评分始终标为未人工核验。
- **服务耗时**从提交复习空间服务到本轮后台动作完成，包含规划、检索与生成，排除索引初始化、额外评审和导出；多轮题分别记录每轮耗时。它不是 HTTP 延迟或流式 TTFT。汇总中位数/P95仅统计成功返回轮次，失败耗时保留在明细。
- **Tokens**使用服务商返回的用量。部分缺失仅报告已知值，完全缺失保持未知，不按 0 算；额外评审独立计费，批量题目的生成用量只计一次。
- **资料外问题与指令遵循**检查是否诚实说明本轮课程依据不足，以及是否遵守用户明确限定。要求“仅依据课程资料”时，展开资料外知识即使标为模型补充仍违反要求；评审需引用实际违反指令的回答片段。`judge.content_score` 保留内容要点分，`judge.instruction_following` 保留指令判定；明确违反指令的题目辅助总分为0。未明确限定时可区分来源补充知识，不强制机械拒答。

`results.csv` 新增内容分和指令遵循判定；报告与 `metrics.json` 新增规划、检索、回答的系统分阶段用量，便于观察召回规划、重排和失败重试开销。阶段数据缺失时不估算填补。旧报告保留原评分口径；本轮评审规则已改变，不能把新旧辅助总分的差异全归因于回答能力。标注片段覆盖指标仍保留严格的文件/页/原文匹配，与等价证据的回答质量判断分开统计。

出处页已选中但引用不在实际提示中，是检查摘录/裁剪的线索；出处页未被选中，需要进一步检查召回与重排。脚本不会仅凭这些线索宣称已经确定根因。

## 人工复核与更新报告

在 `results.csv` 中填写 `answer_correct`、`citation_support`、`outside_handling` 和 `notes`。前三列使用：

- `pending`：尚未检查。
- `pass`：符合标准。
- `partial`：部分符合。
- `fail`：错误、遗漏或编造。
- `not_applicable`：此项不适用。

不要改变题目 ID 或删除行。对照 `gold.json`、课件原文和 `results.jsonl`，特别核对部分正确、补充知识、错用课程口径以及辅助评审意见。CSV会对可能被 Excel 解释为公式的生成文本加文本前缀，原始回答保留在 JSONL。

填写后执行（将路径替换成脚本打印的实际目录）：

```powershell
uv run python .\scripts\evaluate_data_structures.py --summarize ".\data\evaluations\实际结果目录"
```

此命令只读取结果和人工表格，重新生成 `report.md` 与 `metrics.json`，不调用模型，也不覆盖人工判定。报告会同时显示人工通过数量与人工已判题数；pending 不计成正确或错误。

## 比较修改前后

保留 before/after 两份结果目录，对照清单里的题集、标注证据、解析文本、学习记录起点与模型配置哈希，确认只改变了要评估的实现。先修具体失败问题再重跑同一批题，比较分组证据覆盖、人工正确性、动作完成率和开销。不要根据公开题集逐题加别名后宣称泛化能力；后续应另留一批未参与调参的问题。

这 30 题是当前数据结构课程的诊断集，不能代表其他课程，也不等同于纯向量/混合/重排等方法之间的完整消融实验。
